# Game Sandbox

Android-приложение для хакатона «Сбер — Создаем эмоции». Открывает HTML5-игру в WebView так же, как её откроет приложение, и показывает, как приложение реагирует на события со страницы. Повторяет iOS-версию.

## Запуск

1. Откройте папку проекта в Android Studio (JDK 21, compileSdk 36.1).
2. Запустите конфигурацию `app` на телефоне или эмуляторе. Минимальная версия Android 8.0 (API 26).
3. На стартовом экране вставьте ссылку на свою игру или нажмите «Открыть тестовую страницу».

Для игры с dev-сервера на компьютере введите `http://<ip-компьютера>:<порт>`: http разрешён. С эмулятора компьютер доступен по адресу `http://10.0.2.2:<порт>`. Страницу можно отлаживать в Chrome на компьютере через `chrome://inspect`.

## Контракт «страница → приложение»

Страница отправляет обычный `window.postMessage`, приложение подписывается само:

```js
window.postMessage({ type: "COMPLETED_EVENT" }, "*");
```

| Тип | Что делает sandbox |
|---|---|
| `CLOSE_EVENT` | Закрывает экран игры |
| `FINISH_EVENT` | Тост «Игра завершена» |
| `COMPLETED_EVENT` | Тост «Прогресс засчитан». Повторная отправка за одно открытие помечается в логе предупреждением |
| `VIBRATION_EVENT` | Тактильный отклик (`VibrationEffect.EFFECT_CLICK`) |
| `SHARING_EVENT` | Системное «поделиться» с текстом и/или картинкой |

### Шеринг

```js
window.postMessage({
  type: "SHARING_EVENT",
  text: "Я прошёл игру!",
  image: canvas.toDataURL("image/png") // или https-ссылка на картинку
}, "*");
```

Нужно хотя бы одно из полей `text` или `image`. Основной формат картинки — data URL с base64, он работает без сети. Если картинку по https-ссылке скачать не удалось, делимся только текстом.

### Допустимые формы сообщения

Канонический формат плоский, как выше. Также принимаются:

- `{ type, params: { text, image } }`
- `{ data: { type, params: { text, image } } }`
- любой из форматов в виде JSON-строки

## Лог событий

Кнопка справа сверху на экране игры. В логе видно каждое сообщение: время, Origin, исходное тело, распознанный тип и что сделало приложение. Отдельно отмечаются проблемы:

- неизвестный `type`;
- сообщение, которое не удалось разобрать;
- `SHARING_EVENT` без содержимого;
- повторный `COMPLETED_EVENT`;
- заблокированные переходы;
- ошибки загрузки, в том числе HTTP 4xx/5xx и ошибки SSL.

Лог можно скопировать и очистить. На демо кнопку лога можно скрыть на стартовом экране.

## Поведение WebView

Поведение приближено к требованиям хакатона:

- **Без кэша и без сохранения данных.** Каждое открытие начинается с нуля: кэш, cookies и `localStorage` чистятся при открытии и закрытии экрана.
- **Звук и видео** не запускаются без действия пользователя.
- **Переходы за пределы домена страницы и `window.open` блокируются.** Каждая такая попытка попадает в лог: по правилам хакатона у игры не должно быть ссылок наружу и новых окон.
- **Поворот экрана** не перезагружает игру.

## Как устроен мост на Android

Скрипт моста внедряется до загрузки страницы (`WebViewCompat.addDocumentStartJavaScript`) и пересылает `event.data` в приложение через `WebViewCompat.addWebMessageListener`. Канал передаёт только строки, поэтому скрипт заворачивает сообщение в JSON-конверт `{ body }`, а приложение разворачивает его и разбирает тело так же, как iOS-версия. На старом WebView без этих возможностей используется `addJavascriptInterface`, и скрипт ставится после загрузки страницы.

Тестовая страница лежит в `app/src/main/assets` и открывается через `WebViewAssetLoader` по адресу `https://appassets.androidplatform.net/assets/test-page.html`, чтобы у неё был обычный https-Origin.
