# Участник 1 — игровая логика и интеграция

Твоя задача — сделать «Засвет: наклей всё!» работающей игрой. Ребёнок 11–13 лет закрывает вымышленные секреты на кадре, сохраняя главный предмет видимым. Ты отвечаешь за правила, жесты, состояние и сообщения приложения. Участник 2 рисует интерфейс и Canvas; участник 3 готовит сцены и проверяет игру.

Общие договорённости: [01_Project.md](./01_Project.md), разделы 4, 9 и 10. Пример данных: [05_content.example.json](./05_content.example.json). В пакете нет готового игрового кода.

**Результат твоей работы**

Полный сценарий: старт → пять кадров с исправлением ошибок → итог → повтор или выход. Секрет засчитывается только при полном непрозрачном закрытии. Повтор внутри одного открытия не дублирует прохождение курса.

Твои файлы: `game/src/app.js`, `game.js`, `geometry.js`, `input.js`, `content.js`, `bridge.js`. Участник 2 владеет HTML/CSS, `ui.js`, `renderer.js`, `export.js`; участник 3 — `game/data/content.json` и документацией. Изменение общего формата сначала согласуется со всеми.

**Первый час**

1. Создай ветку `feat/gameplay`. Для первой заглушки договорись с участником 2 об одном входном HTML.
2. Создай `app.js` и простые функции моста. Отправляй события по кнопкам, а не при загрузке страницы.
3. Запусти статический сервер в папке `game` и вместе с участником 3 открой страницу в песочнице.
4. Зафиксируй рабочий запуск небольшим коммитом. Не жди финальных рисунков: фон и наклейка пока могут быть прямоугольниками.
5. Согласуй сигнатуры `mountUI`, `updateUI`, `renderBoard`, `createPoster` из общего документа.

**Состояние и функции**

Используй обычные объекты и массивы JavaScript. Для сцены достаточно `levelId`, `placements`, `history`, `checks`, `hintUsed`, `firstCheckPassed`, `locked`. Для всего набора — индекс кадра и записи пройденных сцен. Никакого постоянного сохранения.

- `createLevelState(level)` создаёт пустое состояние.
- `placeSticker(level,state,{stickerId,x,y})` возвращает `{state,accepted,reason}`. Координаты центра нормализованы от 0 до 1.
- `undoPlacement(state)` возвращает снимок до последнего размещения.
- `evaluateLevel(level,placements)` возвращает `{passed,coveredSecretIds,missingSecretIds,blockedKeepIds}` и не меняет входные объекты.

История хранит копии размещений вместе с их `rect`, а не ссылки на изменяемый массив. Новое размещение добавляет один шаг истории; попытка за пределами кадра или при лимите не расходует шаг. В MVP готовую наклейку не двигаем и не вращаем: ошибку исправляют отменой.

После нажатия «Готово» app увеличивает `checks`, записывает исход первой проверки и выбирает сообщение. Сама `evaluateLevel` статистику не меняет. Если подсказка использовалась до первой проверки, не называй её самостоятельной.

После успеха `locked=true`; дальнейшее редактирование отключено. Нажатие «Дальше» создаёт новое состояние. На финале app хранит копию последнего проверенного кадра для постера.

**Геометрия**

`rect=[x,y,w,h]` описывает именно сплошную непрозрачную подложку. Все единицы — доли размеров изображения, не CSS-пиксели всего окна.

При отпускании внутри кадра:

1. Найди секрет, внутрь которого попал центр наклейки. Области секретов в данных не пересекаются.
2. Если он есть, используй его `rect` плюс `stickerPadding` по каждой стороне.
3. Иначе создай прямоугольник `defaultStickerSize` вокруг центра и удержи его внутри картинки.
4. Добавь размещение с уникальным ID текущей сессии.
5. Передай тот же `rect` renderer. Не вычисляй ему вторую геометрию.

Проверка секрета: существует хотя бы одна подложка, полностью содержащая его прямоугольник. Не считай достаточным попадание центра, перекрытие 70% или скрытие части цифр. Объединение нескольких частичных масок в MVP не поддерживается — подгонка делает его ненужным для обычного действия.

Проверка `keepZones`: есть ли пересечение положительной площади хотя бы с одной подложкой. Касание границ без площади пересечения не блокирует кадр. Итоговый `passed=true`, только когда нет открытых секретов и перекрытых обязательных областей. Предусмотри небольшой числовой допуск для сравнений, а не разрешение видимой щели.

Размещение на главном предмете можно показать, но «Готово» объяснит, что он должен остаться видимым. Это делает ошибку понятной и обратимой.

**Жесты на телефоне**

Используй собственные обработчики `pointerdown`, `pointermove`, `pointerup`, `pointercancel`. Во время активного жеста удерживай указатель через `setPointerCapture`; при завершении или отмене сбрасывай preview. Не обрабатывай второй палец как ещё одно размещение.

Для точки на изображении:

```js
const bounds = canvas.getBoundingClientRect();
const x = (event.clientX - bounds.left) / bounds.width;
const y = (event.clientY - bounds.top) / bounds.height;
```

Эта формула подходит при согласованной раскладке: сам Canvas имеет пропорцию 3:4 без внутренних пустых полей. Если вокруг есть CSS-рамка или отступ, координаты берутся относительно области рисунка, а не внешней обёртки.

При отпускании вне картинки ничего не размещай. При `pointercancel` состояние сцены остаётся прежним. Участник 2 ставит `touch-action: none` только на область взаимодействия. Кнопки и обычная прокрутка остальных частей не должны ломаться.

Предусмотри простой способ для мыши и касания: выбор наклейки в палитре, затем нажатие на кадр размещает её. Сначала добейся его работы, затем добавь непрерывное перетаскивание из палитры.

**Загрузка данных**

`loadContent()` загружает `./data/content.json`, проверяет JSON и возвращает конфиг с внутренним флагом `isFallback`. Это поле выставляет загрузчик; автор контента не управляет им.

Проверь: версию формата, непустые массивы сцен/наклеек, уникальность ID, допустимые режимы, конечные числа, `w>0`, `h>0`, границы 0–1, наличие `secrets` и `keepZones`, относительные пути, запас для подгонки и отсутствие пересечений целевых подложек с обязательными видимыми областями. Четырёх размещений должно хватать для всех секретов сцены.

Пути из данных разрешаются относительно `document.baseURI`, то есть `game/index.html`. При повреждённом JSON покажи встроенную простую учебную сцену или экран повтора загрузки. Запасной режим не выдаёт себя за полный набор: **не отправляет `COMPLETED_EVENT`** за исходную игру. Небольшой запасной конфиг хранится в собственном коде, без дополнительного сетевого запроса.

**Сообщения приложения**

Общий вызов — `window.postMessage({type: ...}, "*")`. Используй только существующие типы. Для функций:

- `closeGame()` → `CLOSE_EVENT`.
- `finishOnce()` → `FINISH_EVENT` один раз при первом полном финале.
- `completeOnce()` → `COMPLETED_EVENT` один раз после успешного полного набора, не в запасном режиме.
- `sharePoster(text,image)` → `SHARING_EVENT` с PNG data URL, только после нажатия.
- `vibrate()` → необязательный `VIBRATION_EVENT` при успешной проверке, без спама.

Флаги `completionSent` и `finishSent` принадлежат открытию страницы и не сбрасываются функцией переигровки. Нативный мост не присылает подтверждение и не даёт баланс или данные ребёнка.

Порядок финала: зафиксировать проверенный кадр → показать результат → отправить успешное прохождение/завершение с защитой от дубликатов → подготовить постер → разрешить кнопку шаринга. Если PNG не получен, финал остаётся доступен; недоступность шаринга объясняется спокойно. Автоматически закрывать экран не нужно.

**Что проверить до передачи**

1. Полностью закрытый секрет проходит; частично закрытый — нет.
2. Перекрытие героя мешает успеху, отмена возвращает прежний результат.
3. Четвёртая наклейка разрешена, пятая отклоняется, отмена освобождает место.
4. Отпускание за кадром, отменённый жест и второй палец не оставляют «залипший» объект.
5. Координаты правильны при ширине 360 и 430 и после изменения ориентации.
6. Пять сцен доходят до финала, исправления и подсказки не блокируют прохождение.
7. Повтор в том же WebView не создаёт второго `COMPLETED_EVENT`.
8. JSON с ошибкой не даёт белый экран и не засчитывает весь курс запасной сценой.
9. PNG создан из зафиксированных размещений, перед экспортом тот же снимок снова проходит проверку.

Передай участнику 3 рабочую ветку/коммиты, точную инструкцию запуска, известные ограничения и адрес демо, если он подготовлен. Не отмечай проверку iOS или Android как выполненную без фактического запуска.

Первый важный результат: один кадр в исходной песочнице, где можно закрыть секрет, ошибиться с героем, отменить действие и успешно завершить кадр.
