# Участник 1 — разработчик и интеграция

Твой результат: игра проходит от старта до PNG, не теряет управление на телефоне и отправляет корректные события приложению. Основной код уже написан — начинай с запуска и проверки, затем исправляй реальные проблемы.

## Шаг 1. Запусти и пойми петлю

Из корня проекта:

    python3 -m http.server 8000 --directory game --bind 0.0.0.0

Открой http://localhost:8000. Затем в другом терминале:

    node --test tests/*.test.mjs
    node tools/check-content.mjs

Ожидается 25 успешных тестов и решение всех пяти кадров. После изменения числа сцен тест с явным ожиданием пяти кадров тоже нужно осмысленно обновить.

## Шаг 2. Прочитай модули в таком порядке

| Файл | Что понять |
|---|---|
| src/game.js | Как добавляется наклейка, работает история и проверяются зоны |
| src/geometry.js | Что такое полный охват и пересечение |
| src/app.js | Как состояния экрана меняются после действий |
| src/input.js | Откуда берутся координаты пальца |
| src/renderer.js | Как координаты становятся пикселями |
| src/export.js | Почему экспорт проходит повторную проверку |
| src/bridge.js | Почему повторная игра не засчитывает прогресс ещё раз |

В таблице пути указаны внутри game.

## Шаг 3. Проверь главные функции

**placeSticker(level, state, drop)** получает выбранную наклейку и точку 0…1. Если точка попала на любую записку, наклейка подгоняется под её прямоугольник с запасом. Обычная записка подгоняется точно так же, чтобы размер не выдавал ответ. Если точка вне записки — используется стандартный прямоугольник. Состояние не изменяется на месте: функция возвращает новое.

**evaluateLevel(level, placements)** требует, чтобы каждый секрет целиком входил хотя бы в одну непрозрачную наклейку. Ни одна наклейка не должна пересекать keepZones. Плюс проверяется лимит. Игра не засчитывает закрытие одним уголком.

**undoPlacement(state)** восстанавливает предыдущий массив наклеек. Счётчики проверок и использования подсказки не обнуляются.

**checkLevel(level, state)** записывает число проверок и результат первой проверки. Успех блокирует кадр от дальнейших изменений.

Это небольшие независимые функции. Сначала меняй их, если меняется правило игры; не зашивай правило в HTML.

## Шаг 4. Проверь ввод на телефоне

1. Выбери наклейку, тапни по секрету.
2. Перетащи наклейку из палитры.
3. Начни перетаскивание и отпусти за кадром: ход не добавляется.
4. Начни перетаскивание, поверни устройство: незавершённый ход отменяется.
5. Добавь второй палец: первый жест не должен завершиться чужим пальцем.
6. Нажми «Отменить» несколько раз.
7. На успешном кадре убедись, что наклейки больше не добавляются.

Координаты считай от getBoundingClientRect Canvas. Не используй размеры его внутреннего bitmap для координат clientX/clientY: на экране с devicePixelRatio 2 получится смещение.

Отрисовка запускается через requestAnimationFrame по изменению состояния. Постоянный игровой цикл здесь не нужен.

## Шаг 5. Подключись к официальной песочнице

Участник 3 собирает неизменённое приложение; помоги ему с URL игры. С телефона в той же Wi-Fi-сети нужен http://IP-КОМПЬЮТЕРА:8000. Для стандартного Android-эмулятора README песочницы указывает http://10.0.2.2:8000.

Для публичного показа используйте статический URL с относительными ресурсами. Игра может жить в подпапке: проверь /game/index.html, а не только корень домена.

Контракт:

| Событие | Когда отправляется в этой версии |
|---|---|
| VIBRATION_EVENT | Успешная проверка кадра |
| COMPLETED_EVENT | Открытие финального результата после всех основных кадров |
| FINISH_EVENT | Открытие финального результата, один раз на страницу |
| SHARING_EVENT | Нажатие «Поделиться», с текстом и PNG data URL |
| CLOSE_EVENT | Кнопка × |

Объект bridge создаётся один раз, вне startSession. Не переноси его в повторную игру: иначе сбросится флаг COMPLETED_EVENT. У сообщения нет подтверждения из приложения, поэтому успешный window.postMessage сам по себе не доказывает системный шаринг — смотри лог и окно на телефоне.

## Шаг 6. Сохрани безопасный экспорт

export.js сначала проверяет готовность, затем рисует новый Canvas 720 × 960 тем же renderer. В файл не попадают контуры подсказки и полупрозрачное превью пальца. Под наклейкой всегда сплошная цветная подложка.

Нельзя заменить подложку на один прозрачный SVG, скруглить маску внутрь секретного прямоугольника или сделать глобальную прозрачность. После таких изменений текст может остаться видимым.

Экспортируется один последний подготовленный кадр с наклейками. Сборка пяти миниатюр в общий постер пока не реализована.

## Шаг 7. Принимай изменения команды

От участника 2 бери SVG/CSS; проверяй, что ID кнопок и экранов не потеряны. От участника 3 бери JSON; запускай проверку его схемы и проходимости. Не запускай make-assets.py после ручных правок: он перезапишет их.

После последнего изменения логики, данных или масок выполняй тесты, затем одно полное прохождение в песочнице. Обнаруженная новая ошибка — повод для дополнительного теста; перестановка отступа сама по себе теста не требует.

## Готовность твоей части

- Ни один кадр не блокирует прохождение.
- В консоли нет необработанных ошибок, в Network нет 404.
- В game нет стороннего кода, внешних URL и зависимостей.
- Перезапуск очищает игровой прогресс, но не флаг завершения страницы.
- Работают PNG и сообщения в официальной песочнице.
- Ссылка на публичный репозиторий открывается без авторизации.
