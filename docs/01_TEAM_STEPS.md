# Порядок реализации на троих

## 1. Договоритесь о результате — 15 минут

Делаем «Засвет: наклей всё!» для 11–13 лет. Игрок готовит вымышленную картинку к публикации: закрывает адрес, код, пароль или личную договорённость, оставляя рисунок и обычные идеи видимыми. В конце получает картинку со своими наклейками.

Основная петля: **прочитать → выбрать, что скрывать → наклеить → проверить → исправить → получить кадр**.

Три наклейки одинаковы по возможностям. Их выбор меняет вид коллажа. Никаких комбинаций способностей учить не нужно.

Назначьте роли по навыкам: участник 1 — JavaScript и объединение изменений; участник 2 — графика и интерфейс; участник 3 — уровни, проверка на телефоне и презентация. Если уровни кодирования одинаковые, распределяйтесь по интересу.

Зафиксируйте учебную цель одной фразой из README. Не добавляйте экономику, регистрацию, реальные фотографии и таблицу лидеров до устойчивого прохождения.

## 2. Каждый запускает готовую основу — 20–30 минут

1. Распакуйте полный архив. У всех должна быть одна исходная версия.
2. Откройте терминал в корне проекта.
3. Запустите Python-сервер командой из README.
4. Откройте http://localhost:8000.
5. Пройдите игру целиком. Специально заклейте обычную записку и отмените ход.
6. Участник 1 запускает тесты; остальные проверяют свои экраны.

**Контрольная точка:** каждый видел старт, кадр, ошибку, успех и итоговый PNG. Если старт не открывается, сначала исправляйте запуск. Художественные доработки подождут.

## 3. Сразу заведите общее место для кода — 20 минут

Участник 1 создаёт публичный репозиторий и загружает распакованный проект. При работе через git первоначальный коммит выглядит так:

    git init
    git add .
    git commit -m "Add playable Zasvet prototype"

Затем подключите адрес своего репозитория по инструкции сервиса. Адрес не встроен в игру и не нужен ей во время работы.

Договоритесь, что участник 1 меняет game/src и принимает изменения. Участник 2 работает с styles, index.html и assets; изменения HTML предварительно согласует с участником 1, чтобы не переименовать идентификаторы кнопок. Участник 3 меняет content.json и docs. Один и тот же файл одновременно не редактируют.

Все секреты и обычные записки задаются в JSON. Не рисуйте их текст внутри фона SVG: иначе координаты и видимый текст начнут расходиться.

## 4. Параллельная работа — первые 2 часа

| Участник | Что делает по порядку | Что показывает команде |
|---|---|---|
| 1 | Запуск → тесты → разбор app/game/input/bridge → проверка относительных путей → помощь с телефоном | Полное прохождение без ошибок и понятная схема файлов |
| 2 | Проверка текста на 360 px → кнопки и высота экрана → улучшение трёх наклеек → проверка их читаемости | Один хорошо читаемый кадр на телефоне |
| 3 | Сборка неизменённой официальной песочницы → загрузка URL → проверка сообщений → чтение всех текстов | Игра открылась на реальном устройстве, есть список проблем |

**Особенно важно:** установкой песочницы займитесь сейчас. Ошибка сборки или недоступный URL могут занять больше времени, чем игровые правки.

## 5. Первая общая проверка — через 2 часа

Не обсуждайте «почти готово». Вместе выполните конкретный сценарий:

1. Открыть свежую сессию в песочнице.
2. Убедиться, что звука нет.
3. Наклеить на обычную записку → получить спокойное объяснение.
4. Отменить ход → закрыть секреты → пройти кадр.
5. Повернуть телефон во время перетаскивания. Лишняя наклейка не должна появиться.
6. Дойти до последнего кадра. Подсказка сначала недоступна.
7. Получить PNG и вызвать системное «Поделиться».
8. Пройти повторно в том же открытии. В логе нет второго COMPLETED_EVENT.

Запишите проблемы в одну таблицу:

| Проблема | Приоритет | Ответственный | Что проверит исправление |
|---|---|---|---|
| Игра не открывается в песочнице | P0 | 1 + 3 | Свежий запуск на телефоне |
| Не читается записка | P1 | 2 + 3 | Человек читает без приближения |
| Текст ошибки непонятен | P1 | 3 | Игрок исправляет сам |
| Хочется другую анимацию | P2 | 2 | Делать после устранения P0/P1 |

## 6. Сделайте содержание интереснее — следующие 2–3 часа

Начните с существующих пяти кадров. У каждого есть главный предмет, 2–3 секрета и обычная записка. Секретная и обычная записки выглядят одинаково — ответ выбирают по смыслу.

Участник 3 проверяет, что ситуации различаются. Сейчас есть адрес дома, пароль, код получения/входа и личная встреча у дома героя. Обычные заметки содержат планы рисунка и идеи проекта.

Участник 2 делает юмор заметным: серьёзный носок в очках, облако с портфелем, огурец с крыльями. Это собственные персонажи; не вставляйте изображения известных мемов, брендов и чужие звуки. Финальные реплики — короткие и доброжелательные.

Участник 1 подключает изменения, запускает тесты и проверку контента. Не делает три разных алгоритма наклеек: одна понятная механика важнее дополнительных способностей.

## 7. Измерьте понятность и время — 1–2 часа

Дайте поиграть 3–5 людям, по возможности 11–13 лет. Это небольшая проверка прототипа, а не доказательство эффективности обучения. Участник 3 записывает только наблюдения, без имён и контактов:

| Игрок | Понял первый ход без помощи | Время сессии | Сам исправил ошибку | Последний кадр с первой проверки | Захотел повторить / показать коллаж |
|---|---|---|---|---|---|
| A | Да / нет | мин:сек | Да / нет | Да / нет | Да / нет |

Не объясняйте управление до первой попытки. Если без устной подсказки не получается, исправьте экран. Не принимайте своё быстрое прохождение за результат ребёнка.

По заданию целевая сессия — 3–5 минут. Эта версия пока не измерена. Если медиана меньше трёх минут, добавьте 2–3 содержательно разных кадра через JSON и снова измерьте. Например, секреты в черновике поста, записке у посылки, рабочем столе с кодом доступа. Не заставляйте ждать таймер. Если дольше пяти минут — сокращайте текст и уточняйте обратную связь.

Последний кадр должен остаться mode: transfer. Подсказка до первой проверки недоступна. Не меняйте это ради красивой статистики.

## 8. Финальная сборка и сдача — оставьте минимум 2 часа

1. Участник 1 объединяет изменения. Все прекращают добавлять функции.
2. Он выполняет тесты и проверку контента.
3. Участник 2 проверяет свежую ссылку и PNG на узком экране.
4. Участник 3 проходит список в 06_QA.md в неизменённой песочнице на реальном устройстве.
5. Проверьте открытие той же сборки со второго телефона, если есть возможность. Для приёмки достаточно одной официальной платформы; переносимость на обе остаётся важной.
6. Разместите game на доступном статическом URL. При размещении всего репозитория стартовый URL обычно заканчивается на /game/.
7. В режиме без входа в аккаунт проверьте публичный репозиторий.
8. Внесите ссылку на репозиторий в свою строку общей таблицы.
9. Подготовьте презентацию и один раз проговорите защиту по 07_DEMO.md.
10. Убедитесь, что устройство заряжено, сервер/публичный URL работает, есть запасной интернет и запись успешного демо для подстраховки. Запись не заменяет живой показ.

На странице задания указано: 18 октября, 15:00 — дедлайн кода; часовой пояс явно не указан. Проверьте актуальное сообщение организаторов.

## 9. Что сознательно оставить после хакатона

Больше тематик, новые наборы наклеек, случайный порядок кадров и аккуратная персонализация содержания. Сохранение между входами не закладывайте: хранилище WebView очищается. Реальная аналитика и награды приложения требуют отдельной интеграции, которой в этом прототипе нет.
